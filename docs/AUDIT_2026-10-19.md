# Orestra security/correctness audit — October 19, 2026

## Scope
Ten Orestra repositories; initial source contracts, pure Oreslang modules,
Python conformance oracles, static website/dashboard, and CI source/test gates.

## High-impact findings and changes

| Finding | Risk | Response | Status |
|---|---|---|---|
| Reservation was not an atomic multi-object commit in reference state | Double placement / overcommit | Fenced CAS reservation + binding at one revision | Reference fixed; production pending |
| Unreachable node mistaken for terminated workloads | Duplicate physical workload execution | Unknown counts as unresolved until external fence proof | Reference fixed; production pending |
| Watch cursor revision could skip siblings of one transaction | Silent missed controller event | Per-event resume cursor, RESET_REQUIRED after compaction | Reference/API/SDK fixed |
| API validation only checked required top-level fields | Unknown fields / illegal quantities admitted | Draft 2020-12 schema validator + negative cases | Test contracts improved |
| Driver manifest validation used Python assert | -O disables checks; unsafe plugin metadata | Explicit ValueError and malicious test vectors | Oracle fixed |
| CLI placement accepted bad inventory shapes | Invalid candidate selection and traceback | Bounded, signed-i64 and uniqueness checks | Offline tool fixed |
| Browser allowed ambiguous proxy inputs and unbounded lists | Credential confusion / resource exhaustion | Canonical path, bounded list, text rendering and JS unit tests | Console improved |
| Website implied unmeasured overhead benefit | Misleading performance claim | Removed claim; added CSP and link regression checks | Fixed |
| Green Oreslang source checks did not compile sources | False integration confidence | Compiler-release gate explicitly documents deficit | Gate tracked, pending |

## Outstanding blockers (in priority order)

### Critical — release blocking
- **Oreslang native compiler**: compile and run all relevant source examples on
  GraalVM, then LLVM. Current CI only checks structure/import paths.
- **Durable state**: WAL, Raft, consistent transactions, authenticated
  versioned watches, crash recovery and state snapshots in Oreslang.
- **OCI runtime**: privileged node agent, authorized process isolation,
  idempotent commands and verified runtime termination.
- **Security**: mTLS service identities, RBAC, admission/quota, secret
  encryption and audit log.

### High
- Endpoint auth, browser session integration and API-backed UI.
- CSI/CNI integration with capacity/fencing guarantees.
- Recovery after node partition and safe workload eviction.
- Protocol compatibility tests and resource schema migrations.

## Non-claims
Passing Python reference tests does not establish linearizability in a
replicated cluster, OS isolation, Kubernetes conformance or production
readiness. Do not silently substitute the test oracle for an Oreslang
storage implementation.

## Integration policy
Use pinned SHA fixtures from `integration/compatibility.lock.json`.
CI must explicitly record which source was compiled and whether backend
parity and OCI execution actually occurred. A `passed` static check is
not a production release qualification.

## Added verification infrastructure

- Orestra State now includes concurrent reservation contention tests and
  bounded epoch fencing exploration, in addition to a stronger TLA+ model.
- Orestra Conformance includes a fail-closed executable native fixture harness
  for the real GraalVM/LLVM runners, with explicit missing-runner refusal.
- Unknown/Terminating workload claims continue occupying resources until
  the corresponding physical stop or fence is independently verified.
