ENGINEERING / ARCHITECTURE

Actors at the control plane. Standards at the edges.

Orestra is built around a versioned declarative API, a strongly consistent resource store, supervised controller actors, a deterministic scheduler and authenticated node agents. These components are still under development.

Authority boundaries

The state store is authoritative for desired state and placement commits. Scheduler workers may score candidates on immutable snapshots, but only atomic version-checked reservations are binding.

Core / alloc / stdlib

Freestanding Oreslang core defines ownership, typed state machines, error results and atomic contracts. Allocation, actor supervision, Tasks, network protocols, storage and Linux host operations remain optional layers.

Safety

Leader epochs and CAS prevent stale control-plane writers. Node processes may continue running during a network partition: a lost heartbeat is not proof that external side effects have stopped. Isolating untrusted OCI workloads requires kernel safeguards beyond actor heaps.

Compatibility

OCI, CNI and CSI are planned adapter boundaries. Native Orestra schemas are not Kubernetes API compatible yet.
